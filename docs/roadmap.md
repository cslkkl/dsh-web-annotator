# 路线图

长期主线是“直接指出网页上的位置，让 Agent 理解问题并给出可验证的答复或修改”。优先让常用流程稳定，避免靠增加检测规则扩大产品范围。

1. 完成官方 Browser 扩展接口的评审与真实 Desktop 验收，让用户能正常安装插件，而不是自行应用宿主补丁。
2. 接入原生区域截图和正确的会话附件 API，先验证缩放、滚动、跨屏像素比例与实际附件日志，再声称视觉证据已送达模型。
3. 验证真实模型根据批注定位并修改源码；增加修改前后同一区域对比，以及“提问只回答”的回归场景。
4. 处理长期使用：批注编辑、过期定位提示、页面变化后的重新定位、批注导出与版本迁移。
5. 建立支持版本矩阵和发布流程，先支持明确验证的 Harness / 浏览器 / 项目组合，再扩大兼容范围。

这些是维护优先级，不代表已实现功能或发布时间承诺。独立插件负责批注流程与请求质量；浏览器载体、权限和拓展接口应由 Harness 维护。
