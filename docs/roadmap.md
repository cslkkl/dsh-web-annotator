# 路线图

长期主线：直接在网页上指出位置，让 Agent 理解问题并给出可验证的答复或修改。
优先级排序以“让常用流程稳定”为准，不靠增加检测规则扩大范围。

## 1. 让安装不再依赖替换官方提供方

Browser 补丁合入官方 Harness 之前，用户装的包会替换 Browser / Chat / Layout 三行。
这是当前最大的安装摩擦，也是“用户能正常安装”的前置。

## 2. 补上截图与附件的完整验收

原生视口捕获目前只经人工验证，自动化里用测试替身代替了 Electron 边界。
需要验证缩放、滚动、跨屏像素比例与实际附件日志，再声称视觉证据完整送达。

## 3. 验证真实模型改动源码

需要真实模型按批注定位并修改前端源码，并覆盖“提问只回答、不改代码”的回归场景。
在此之前，任何“全流程通过”的说法都不成立。

## 4. 长期使用

批注编辑、过期定位提示、页面变化后的重新定位、批注导出与格式版本迁移。

## 5. 支持矩阵与发布流程

先明确验证过的 Harness / 浏览器 / 项目组合，再扩大兼容范围；
稳定版发布前补齐官方 monorepo 门禁与稳定 dist-tag。

以上是维护优先级，不代表已实现功能或发布时间承诺。
独立插件负责批注流程与请求质量；浏览器载体、权限与扩展接口应由 Harness 维护。
