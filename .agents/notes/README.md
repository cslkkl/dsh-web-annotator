# notes/ — 决策记录

记录“当时为什么这么定”，以及被打败的替代方案。

## 命名

`YYYY-MM-DD-<主题>.md`，主题用英文 kebab-case。

## 状态行

每篇第 3 行写状态，取值 `生效` / `被取代` / `已否决` / `已归档`。
`被取代` 跟指针行，`已归档` / `已否决` 跟一句话理由。失效笔记就原地标注，不移动文件。

## 每篇的结构

照这个骨架写，`## 替代方案` 是强制的：不记录被打败的选项，下次必被重诉。

```markdown
# 决策：{标题}（YYYY-MM-DD）

状态：生效

## 问题

{为什么需要这个决策；现状造成了什么代价，各列一条。}

## 决策

{用现在时描述 shipped 事实。路径、默认值、机制名写准。}

## 替代方案

- {方案 A}：为什么不行
- {方案 B}：为什么不行

## 影响

{代价与收益；对外可观察的变化要点名，并指向同步过的文档。}
```

判断标准：**读者拿这篇能不能不重提已经被否掉的方案。** 不能就是写少了。
